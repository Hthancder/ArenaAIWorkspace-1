# v2.9.0 — Thiết kế đầy đủ: **Việc lặp lại** (recurrence, first-class)

> Trạng thái: **SPEC — chưa code**. Theo yêu cầu: chỉ thiết kế, không ship.
> Nguồn cảm hứng trực tiếp: phản hồi của user trên v2.7.0/v2.8.0 —
> "lặp bao ngày, đến ngày nào?, khi tạo task lặp thì có cả 1 bảng lịch ảo cho chọn ngày…" + "TUỲ CHỈNH CAO".

---

## 1. Mục tiêu & phi mục tiêu

**Mục tiêu**
1. Việc lặp là **công dân hạng nhất**: tạo–sửa–dừng–bỏ qua được từ mọi nơi, mọi thao tác đều có lối về (Ctrl+Z).
2. **Đầy đủ quy tắc**: tần suất (ngày/tuần/tháng/năm), **khoảng lặp tùy ý** (mỗi N đơn vị), **chọn thứ trong tuần** (tuần), **ngày trong tháng** (tháng, gồm "ngày cuối cùng"), **kết thúc**: không bao giờ / đến ngày / sau N lần hoàn thành.
3. **Bảng lịch ảo (ghost calendar)** trong lúc tạo/sửa: *thấy trước* các ngày việc sẽ xuất hiện, bấm ngày bất kỳ để đặt hạn kết thúc.
4. **Câu tóm tắt người-đọc-được** cập nhật trực tiếp: *"Mỗi 2 tuần vào Thứ Hai & Thứ Năm, đến 31/12/2026 (~19 lần nữa)"*.
5. **Cùng 1 mô hình dữ liệu chạy được cho cũ lẫn mới** — dữ liệu v2.8.0 (Daily/Weekdays…) tự nâng cấp, không mất gì, không cần user làm gì.
6. Nhất quán triết lý app: **layer-1** (không AI), **ADHD-safe** (copy dịu, không đếm ngược shame), **hoàn tác được mọi thứ**, tiếng Việt.

**Phi mục tiêu (v1 của tính năng)**
- Không sync đám mây / không RRULE string tương thích iCalendar (xuất được sau này nếu cần).
- Không xử lý ngoại lệ từng instance ("dời lần này sang mai, các lần sau giữ nguyên" — phase sau).
- Không parser ngôn ngữ tự nhiên cho interval (`*mỗi 3 ngày`) — phase 2, ghi nhận ở §11.
- Không "chuỗi vô hạn hiển thị sẵn trên lịch" (không materialize) — xem §4.1.

## 3. Nguyên tắc thiết kế (đứng trên vai 5 bản ghi chú của user)

1. **TUỲ CHỈNH CAO là điều kiện thắng** — mọi thứ chỉnh được, xóa được, hoàn tác được. Không có chế độ "ẩn" nào chạy không có sự đồng ý.
2. **Không đánh đố**: mỗi việc lặp luôn nói được *bây giờ lặp kiểu gì, còn bao lâu lặp nữa*.
3. **Một chỗ duy nhất để chỉnh**: modal "Lặp lại" — detail panel chỉ là cửa vào.
4. **ADHD-safe**: không đếm "chuỗi 12 ngày" như quota; copy nhắc nhở dịu; không đỏ.
5. **Lỗi nhẹ = lùi an toàn**: mọi thao tác (kết thúc, bỏ qua, đổi rule) = 1 undo.

## 4. Quyết định kiến trúc

### 4.1 Instance-based (giữ) vs Virtual occurrences (bỏ qua)

**Giữ mô hình "clone khi hoàn thành"**, nâng cấp rule. Lý do thật (không phải vì ngại đổi):

| Tiêu chí | Clone-on-complete | Virtual (compute occurrences) |
|---|---|---|
| Undo/Redo | `store.clone()` trước thao tác → hoàn tác *cả series lẫn lần vừa tạo* ✓ miễn phí | Mọi chỗ đọc (list, counts, stats, focus timer, drag&drop…) phải hiểu "phần tử ảo"; undo phức tạp gấp nhiều lần |
| Sao lưu/đồng bộ file JSON | Không đổi | Định dạng file thay đổi sâu |
| "Sửa rule" giữa chuỗi | Rule nằm trên instance đang sống → lần clone kế tiếp dùng rule mới ✓ tự nhiên | Phải version rule theo thời điểm |
| Completions "quái" (hoàn thành 3 lần trong 1 ngày) | 3 instance Consecutive — không sinh ngày trùng nếu rule theo ngày | Cũng ổn, nhưng *không* sâu hơn cho nhu cầu user |
| Chi phí triển khai | Thấp, rủi ro thấp | Viết lại ~nửa app |

**Nguyên tắc bù trừ** (khiếm khuyết đã biết → cách xử):
- *Không biết lần thứ N trước khi xảy ra* → modal **bắt buộc** hiển thị lịch ảo + đếm "≈ N lần nữa" (xem §8.2) → user nghiệm thu ngay trong lúc tạo.
- *"Lặp đến ngày X"* → enforce **ngay lúc hoàn thành** (không tạo instance nếu vượt `until`/hết `after`) **và** khi *tải/sanitize*: instance chưa-hoàn-thành có rule đã hết hạn → tự động chuyển thành việc thường (rule → `None`), flash một lần "việc lặp đã hết hạn — chuyển thành việc thường".
- *"Bỏ qua lần này"* → action mới `skip_occurrence`: đẩy `due` sang occurrence kế tiếp, **không** đánh dấu hoàn thành, không đếm `after`, undo được.

### 4.2 Rule model mới (serde-tương thích ngược)

```rust
/// Lặp theo tần suất — mở rộng thay cho enum Repeat.
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct RecurrenceRule {
    pub freq: Freq,             // Day | Week | Month | Year
    #[serde(default = "one")]
    pub interval: u32,          // 1..=99 — "mỗi N đơn vị"
    /// Week: bitmask Mon..Sun (bit0 = Thứ 2 … bit6 = Chủ Nhật). None = đúng thứ của due.
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub by_day: Option<u8>,
    /// Month: 1..=31 hoặc -1 = ngày cuối cùng của tháng. None = đúng day-of-month của due.
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub month_day: Option<i8>,
    #[serde(default)]
    pub ends: EndSpec,          // Never (default) | Until(date) | After { total, done }
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
pub enum Freq { Day, Week, Month, Year }

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
#[serde(tag = "kind", rename_all = "snake_case")]
pub enum EndSpec {
    Never,
    Until { date: NaiveDate },
    After { total: u32, done: u32 },
}
```

**Chiến lược serde (không bump `current_version() = 1`, không vỡ file cũ):**
- Task giữ **cả hai** trường: `repeat: Repeat` (legacy, `#[serde(default)]`) và `recurrence: Option<RecurrenceRule>` (`#[serde(default)]`).
- `Store::sanitize()` (chạy mỗi lần nạp):
  1. `recurrence == None && repeat != None` → nâng cấp: `Daily→{Day,1}` ; `Weekdays→{Day,1,by_day:0b0011111}` ; `Weekly→{Week,1}` ; `Monthly→{Month,1}`. `done` của `After` khởi tạo = số instance đã hoàn thành của chuỗi nếu đếm được (best-effort: chỉ áp cho `After` do user tạo mới).
  2. Ghi ngược `repeat = shadow(recurrence)`: rule "đơn giản" → lại `Daily/Weekdays/Weekly/Monthly`; rule custom → `None` (build cũ mở file này sẽ thấy "Không lặp", **không** nhân bản loạn — lùi an toàn).
- Build mới **chỉ dùng** `recurrence` cho logic; `Repeat` chỉ còn vai trò shadow cho tương thích ngược.
- Export/backup đi kèm cả hai trường — không mất gì ở mọi chiều.

### 4.3 Thuật toán occurrence kế tiếp (chuẩn hoá, dùng chung Rust+JS)

```
fn next_after(rule, from: NaiveDate) -> Option<NaiveDate> {
    match ends {
      After { total, done } if done >= total => return None,
      Until { date } => {} // kiểm tra sau khi tính
      _ => {}
    }
    let base = match freq {
      Day   => from + interval ngày,
      Week  => nếu by_day: ngày kế tiếp (sau `from`) có bit bật, bước tuần nếu cần;
               không by_day: from + 7*interval,
      Month => from + interval tháng, clamp day (31/1 + 1th → 28/29-2), hoặc month_day (-1 → ngày cuối),
      Year  => from + interval năm, clamp 29/2 → 28/2,
    };
    nếu Until{date} và base > date → None
    Some(base)
}
```
- `by_day` rỗng sau khi user bỏ hết → **không cho lưu** (tự quay về "đúng thứ của due").
- `interval=0` → clamp về 1; >99 → clamp 99.
- `Until < hôm nay` → validation chặn ngay trên UI (không cho Lưu).
- Test phải khoá: clamp 31→28/29, `until` biên (đúng ngày = OK, sau 1 ngày = hết), `after` hết khi `done == total`, mask `0b0000101` (T2+T6), leap year, `Weekly` từ due Chủ Nhật.

### 4.4 Hoàn thành — luồng mới

```
Act::Toggle(id):
  push_undo
  task.completed_at = now
  if let Some(rule) = task.recurrence {
      match next_after(&rule, task.due.unwrap_or(today)) {
        None => {
            // chuỗi kết thúc ngay lần này
            set_flash("✓ Hoàn thành — chuỗi lặp đã kết thúc");
            // giữ rule trên instance đã xong để lịch sử còn ý nghĩa
        }
        Some(next) => {
            if let After{total,done} = rule.ends { done += 1 }
            spawn clone { due: next, occurrence mặc định bỏ chọn, starred=false }
            set_flash("✓ Xong — lần tiếp theo: <Thứ>, dd/mm/yyyy");
        }
      }
  }
```
- **Undo** = `store.clone()` từ trước → hủy luôn cả hoàn thành lẫn clone — không đổi.

### 4.5 Bỏ qua lần này (skip occurrence) — action mới

`Act::SkipOccurrence { id }`:
1. `push_undo`
2. compute `next` từ rule + due hiện tại; **không** đụng `completed_at`; set `task.due = next`; (nếu `After` → **không** tăng `done`).
3. flash "Đã bỏ qua — lần tiếp theo: <Thứ>, dd/mm/yyyy" + undo.

Hợp lý cho: nghỉ ốm, đi công tác, "hôm nay không tập — tiếp tục lịch từ mai".

### 6.1 Detail panel (điểm chạm chính)

```

│ ┌─────────────────────────────┐ ┌───────────┐ │
│ │ ↻ Mỗi 2 tuần · T2 & T5      │ │  Chỉnh…   │ │
│ │    đến 31/12/2026           │ └───────────┘ │
│ └─────────────────────────────┘               │
│ Hoàn thành xong → lần tiếp theo: T5, 27/11/…  │
│ [Dừng lặp lại]  [Bỏ qua lần này]              │
```

- Nút tóm tắt mở modal (§6.2). Nút "Chỉnh…" đồng nghĩa.
- "Dừng lặp lại" = set `recurrence=None` (giữ việc); "Bỏ qua lần này" = skip (§4.5). Cả hai **1 click**, undo được.
- Việc thường (không lặp): hàng nút hiện "Không lặp" + nút "↻ Lặp lại…" (mở modal tạo mới).

### 6.2 Modal "Lặp lại" — đặc tả đầy đủ

Mở từ: detail panel; chip ↻ trong quick-add (khi đang gõ việc); command palette ("Lặp lại…").

**Kích thước**: 460–520px, scroll trong nếu màn thấp. **Focus trap** theo modal system sẵn có. Esc đóng (hủy thay đổi — mọi thay đổi chỉ áp dụng khi bấm **Lưu**).

```
└──────────────────────────────────────────────────────┘
```

**Ghost calendar — đặc tả chi tiết**
- Header: `‹` tháng/năm `›`; giới hạn: không lùi trước tháng hiện tại, chỉ tới **until** (hoặc 24 tháng).
- Lưới 7×6 (42 ô), header thứ T2..CN; ô = ngày; **trạng thái ô**:
  - *quá khứ*: mờ (không tương tác);
  - *hôm nay*: viền accent;
  - **ngày việc xuất hiện**: nền tím mờ + chấm đặc (`.occ-dot`);
  - *ngày kết thúc (until)*: nền tím đặc, chữ trắng; sau đó dim toàn bộ;
  - hover: scale 1.06 (reduce-motion: tắt) + tooltip "Tập thể dục — lần #7".
- **Bấm vào một ngày** → nếu đang chọn "Đến ngày": đặt `until = ngày đó`, lưới re-render, summary cập nhật. Nếu không: chỉ xem, không đặt gì (không side-effect ẩn).
- Dòng dưới: "≈ N lần nữa" đếm occurrence từ hôm nay → `until | vô tận (giới hạn đếm 200 để hiển thị)`.
- **Empty-state**: rule chưa có occurrence nào tới (ví dụ chọn thứ 2 nhưng hôm nay là thứ 3 và interval lớn) → hiện "Thứ T3 chưa có lần nào trong 12 tháng tới — kiểm tra lại thứ trong tuần".

**Validation & lỗi (inline, không popup)**
- `interval` ngoài 1..99 → kẹp + viền đỏ nhấp nháy nhẹ.
- `by_day` rỗng → viền đỏ + hint "Chọn ít nhất 1 thứ".
- `until < today` → viền đỏ + "Ngày kết thúc phải ở tương lai".
- `after.total < 1` → kẹp 1.
- Lưu **disabled** khi có lỗi — không bao giờ lưu rule hỏng.

### 6.6 ADHD mode
- Copy dịu, không quota, không đếm "streak lặp". Confetti khi hoàn thành vẫn chạy (reward tức thì).

### 6.7 Accessibility
- Calendar grid: `role="grid"`, ô `role="gridcell" aria-selected`, điều hướng mũi tên, Home/End = đầu/cuối tuần, `PageUp/Down` = chuyển tháng, `Enter` = chọn ngày (đặt until khi ở chế độ "Đến ngày").
- `:focus-visible` ring accent; mọi nút icon có `aria-label`; reduce-motion tắt scale/fade.
